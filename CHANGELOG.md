# Changelog

### 2.2.1
KitchenSink4Word 2.2.1 is a fix release shaped by a real dissertation build driven through the server and the review rounds that followed.

- **A misspelled pack lock now fails closed.** `KS4W_PACK_POLICY` accepts only `auto` or `locked`, ignoring case and surrounding spaces; an empty value means `auto`. Any other value stops startup with exit code 2 and a clear stderr message, and the value is checked again whenever the policy is consulted. A misspelling used to leave optional packs switchable. A correctly spelled `locked` behaves as before, and the `enable_tools` refusal now explains that the host fixed the tool surface at startup and that a person must change the launch setting before retrying.
- `enable_tools` now always says what happened and what to do when a client fixed its tool list at startup. It reports whether `tools/list_changed` was sent or the requested packs were already on. In the Claude Desktop extension, turn on **Load every tool at startup**, restart Claude Desktop, and start a new session. In a hand-configured client, put a comma list of packs in `KS4W_MODE`, restart the app or session, and then start a new worker if needed. Claude Code can instead enable packs in its main session before it starts workers. The server instructions and `get_workflows` now also say that workers and subagents see only the tools that were on when they started. A locked policy still caps the surface.
- The 14 tools with a `live` parameter now publish its accepted values in their schemas: `auto`, `force`, and `off`. `auto` can use the file or the open document, `force` goes straight to the open document, and `off` refuses rather than going live. The accepted values and their behavior are unchanged; clients no longer need to guess them.
- A malformed `location` refusal now gives the whole grammar: exactly one selector plus an optional `position`, whose accepted values are `before`, `after`, `replace`, `start`, and `end`, with `after` as the default. It includes examples for `paragraph`, `after_heading`, `outline`, `bookmark`, `search`, `anchor`, and `cursor`, and says that `cursor` needs the document open in Word. The accepted locations and the compact published schema are unchanged.
- The `format_text` description now states that `find` formats only the matched substring, splits the run at the match, and preserves the run's other formatting on every fragment. The `merge-chapters` guide no longer steers callers away from `find`. The behavior itself is unchanged.
- The table tools now point callers to `format_cells` for shading and cell formatting, `set_table_properties` for column widths and a repeating header row, and `modify_table_structure` for reshaping. `format_cells` also accepts `{"row": "header"}` to target the leading rows marked to repeat as headers, or row 0 when none is marked. Other strings and true/false values are refused; use a 0-based integer for an ordinary row.
- Each `insert_paragraphs` item can now carry `paragraph_format` with the same keys as `set_paragraph_format`. It is applied after cloned formatting, so stated values win. Every item is checked before insertion, and one bad key refuses the whole call without touching the file. This route works on closed files; for an open document, close it and retry or insert first and follow with the live-capable `set_paragraph_format`.
- COM operations that run in an invisible Word no longer force-end Word when they time out. After the timeout, the server waits 10 more seconds and returns the real result or error if Word answers. If Word still has not answered, `APP_BLOCKED` says that the operation was not cancelled, may still finish and save its output, and should not be retried until `com_word_status` reports no COM operation in progress and the output file has been checked. The refusal reports the Word process it observed and the title of any open Word dialog. In verification, a timed-out export wrote its PDF 100 to 130 seconds later.
- A `com_` call whose own timeout passes while it is still queued behind another COM operation is now abandoned and never runs. Its `APP_BUSY` refusal says that it made no document changes and is safe to retry after `com_word_status` reports no COM operation in progress. KitchenSink4Word 2.2.0 left that call queued, so a retry could run the same operation twice. A call that already started follows the timeout rule above.
- Live calls and passwordless `com_save_document` calls now refuse immediately with `APP_BUSY` when Word is already in use, before touching the open document. Nothing from the refused call is queued to run later. Save and close now also respect the machine-local cross-process lock because they temporarily change Word's application-wide alert setting. The generic `APP_BUSY` hint now directs callers to follow the specific error message and retry only after its stated condition is resolved. Hidden-Word `com_` calls keep their bounded-wait behavior described above.
- Invisible Word cleanup now closes that instance's remaining documents without saving before asking Word to quit, reports a failed Quit on stderr, and waits up to 6 seconds for the process to exit. If the process it started is still present, the server says that WINWORD.EXE may be lingering and is safe to end in Task Manager; it does not end the process. Process checks run without flashing a console window.
- The descriptions for `com_multi_document`, `com_proofing_errors`, `com_readability_statistics`, and `com_validate_opens_clean` no longer claim that the call aborts after its timeout. Their timeout ranges and defaults are unchanged. `get_workflows` also now explains that `com_refresh_fields` updates tables of contents and tables of figures one by one because the Word automation collection has no single update call.
- The surface remains 222 operations: 110 document tools plus `enable_tools` and `disable_tools`. A lite start exposes 29 tools at about 10,200 tokens, and the full surface is 112 tools at about 35,500 tokens. The suite contains 2,189 tests, including 95 that drive a real Word on Windows.

### 2.2.0
This release changes what several calls return and what some of them write. The first three entries can break code written against 2.1.3, so read them before you upgrade. `com_refresh_fields`, `get_outline(detect_formatted=true)` and `list_elements(type="toc")` also return more or different data, and `insert_document` with `formatting="source"` writes more direct formatting than it did; each is described in its own entry below.

- **`validate(checks=["citation_parity"])` returns a different result.** `missing_references` now holds only unmatched citations whose author is a single surname. Unmatched citations with a longer author phrase (organizational authors such as "National Archives (2003)", and two-author citations such as "Smith and Jones (2020)") move to a new key, `missing_references_unparsed`; 2.1.3 mixed them into `missing_references`. Both lists need attention. `reference_entries` counts every entry in the reference list, with `reference_entries_parsed` beside it; it used to count only the entries that parsed, so it disagreed with the document. A citation that could not be matched never passes: `passed` is false whenever either list has anything in it, and `missing_references_unparsed_reason` says why the citations in the second list were not resolved. Anything that parses this result gets different data for the same document.
- **`define_style` on a style that already exists updates it in place.** 2.1.3 removed the style and rebuilt it from the call, so everything the call did not mention was lost, including the marker that makes a style the document's default paragraph style, and the result reported success anyway. Now attributes are kept, and paragraph and run formatting merge with what is there. `based_on` left out means "Normal" when the style is new and "leave the parent alone" when it exists; `based_on=""` clears the parent, and `get_styles` reports `""` for a style with no parent, so reading a style and defining it again round-trips. Changing an existing style's type in place is refused, because content that uses the style would break. The result says `unchanged: true` when the call changed nothing, and reports `replaced` only when the style really changed. `qFormat` is no longer added to a style the call only updated.
- **`format_text` with a `range` and no `find` formats whole paragraphs, including the paragraph mark.** 2.1.3 touched the runs of one paragraph and left the paragraph mark in its old formatting. A range of several paragraphs is now accepted when the file is closed; text inside text boxes is skipped. The result changes with it: this path returns `{"formatted_paragraphs": [...], "runs_formatted": N}` where it used to return `{"formatted": {start, end, paragraph}}`. The `format` op inside `apply_edits` behaves the same way when it has no `find`. A call that gives `find` works as before and returns the old result. On a document open in Word it still takes one paragraph per call and says so.
- New: `apply_edits` can move paragraphs. `{"op": "move", ...}` relocates paragraphs exactly as they are, so their formatting, hanging indents and bookmarks travel untouched. It refuses to move a paragraph that carries a section break, refuses a destination inside the block being moved, and refuses to land paragraphs in a different section, where they would take on that section's page setup, headers and footers, unless the op says `allow_cross_section: true`, which does it and warns. Every refusal leaves the file byte-identical. It works on closed files; on a document open in Word it refuses and points to the file route.
- `insert_document` with `formatting="source"` now keeps what the source really looked like. Where the two files resolve the same thing differently (document defaults, styles that share a name, theme colours), the carried content gets the source's values written on it directly. This covers bold, italic, colour, underline, borders, shading, tabs, frames and the paragraph mark, follows a style's whole chain of parents, and no longer writes an indent onto a numbered paragraph, which used to push list text out of line. The result says which shared style names caused each difference and lists anything it could not write, each with a plain reason; theme fonts are reported that way instead of being guessed.
- Theme colours survive a merge between two templates. The same theme colour name can mean two different colours in two files, and the theme does not travel with the content. Carried text, shading and borders that use a theme colour are now written as fixed colours wherever the two files disagree, tints and shades included, matching what Word itself displays. Page borders and the page background are not carried by `insert_document` at all, so they are not part of this. Those colours no longer follow the target's theme afterwards, and the result says so under `theme_colors`. Files with identical themes are left exactly as they were.
- A table style whose name exists in the target with a different look is brought in as "X (imported)", and the carried tables point at it, so they keep their appearance. Inserting from the same source again reuses that copy instead of adding "X (imported 2)", and the result names the style it reused.
- With tracked changes turned on, the `move` and `delete` ops warn that the edit was applied directly and will not show up as a revision. Documents that do not track changes get no warning.
- `com_refresh_fields` reaches every header, footer and other text area in every section; 2.1.3 updated only the first of each kind. It reports counts per area and counts tables of figures separately from tables of contents. One limit is now stated in the tool description: page-number and page-count fields inside headers and footers keep their stored text until Word lays the pages out, which happens when the document is opened.
- `get_outline(detect_formatted=true)` finds headings more reliably in documents that do not use heading styles. Bold and centering that come from a paragraph's style are seen, a short centered title is detected, numbered captions such as "Table 3." and bold lead-ins ending in a colon are left out, and every guessed heading carries a `confidence` value. These entries are candidates with an inferred level, and the tool descriptions say so.
- `list_elements(type="toc")` reports each table of contents with its own entries. When a document had more than one, every one of them used to be listed with the entries of all of them.
- `define_style(first_line_indent_pt=...)` on a style that had a hanging indent now produces the first-line indent. It used to produce no indent at all.
- `get_workflows` has three new guides: `merge-chapters`, `build-lists-without-heading-styles` and `merge-reference-lists`.
- 222 operations across 110 tools (one more operation than 2.1.3: `move`).
- The MCP Registry entry moves to the `io.github.KitchenSink4AI` namespace and is published from the release workflow.

### 2.1.3
- `get_server_info`: the Word registration probe no longer calls a pywin32 attribute that does not exist. It read the registration through `pythoncom.CLSIDFromProgID`, which pywin32 has never had, so the call raised on every machine and the report said Word was not registered even where Word was installed and automating. The probe now reads the registry directly.
- Probe failures are reported instead of hidden. A probe that cannot answer says so, and a registered Word, an absent one, and a failed lookup are three different answers rather than two.
- A document mutation or a live Word session that runs longer than ten minutes keeps its lock. Both locks were previously broken on age alone even while the holding process was alive, which let a second writer into the same file and reopened the race the locks exist to close.
- A lock written by another machine is never reclaimed from this one. A PID number on a network share says nothing about a process on a different computer, so a foreign-host lock now makes the waiter wait and then refuse by name.
- Runtime hints and error messages no longer contain em dashes, which some terminals and log pipelines render as replacement characters.
- Fixes #24.

### 2.1.2

It said the AGPL made this free for any use, which skipped the AGPL's source-sharing obligations and read as though no commercial license existed. The notice, the README, and the landing page now state the dual license plainly, and licensing@kitchensink4.ai is the address for it.

### 2.1.1
- The server reported the framework's version number instead of its own when a client connected. It now reports the version you installed.
- The server introduces itself by name. A connected agent can tell it is talking to KitchenSink4Word, and `get_server_info` now returns the product name, the package name, the landing page, and the rest of the family.
- Published addresses point at kitchensink4.ai.

### 2.1.0
- Update notice: the server checks PyPI for newer releases at most once every seven days, says so in its own payload, and turns off with KS4W_UPDATE_CHECK=off. It never downloads anything.
- Table reads cost about a quarter of what they did; merge fidelity is unchanged and pinned.
- Documents open roughly twice as fast.
- The window-binding layer is consolidated and hardened against a crash class found in live testing.
- The install screen and info card are rewritten in plain language.
